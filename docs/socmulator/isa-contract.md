## Gemmini

### Instruction envelope and common rules

`XCUSTOM_ACC=3`, custom-3 (`opcode=0x7b`), selects the accelerator. The config defaults to `OpcodeSet.custom3`; instruction funct7 values below are seven-bit values. Ordinary operations use `xd/xs1/xs2=0/1/1`, funct3=3, rd=x0; COUNTER uses `1/1/1`, funct3=7, rd supplied by the caller. rs1/rs2 descriptions assume RV64; operands holding addresses are byte addresses unless explicitly local row addresses. Sources: `G/src/main/scala/gemmini/GemminiConfigs.scala:17-18,330-341`; `G/software/gemmini-rocc-tests/include/gemmini_params.h:7-9`; `G/software/gemmini-rocc-tests/rocc-software/src/xcustom.h:49-77,115-152`; opcode literal cross-check `P/PoTalIndexRoCCAdapter.scala:132-133`.

All ordinary commands below have **no CPU rd response**. Acceptance into the raw queue is issue, not execution completion. Loads/stores have DMA trackers; execute has a separate completion path; the reservation station receives all three. Load/store configuration entries can retire from the reservation station on issue, before subsequent data commands finish. Sources: `G/src/main/scala/gemmini/Controller.scala:131-160,312-330`; `G/src/main/scala/gemmini/ReservationStation.scala:343,409-446`; `G/src/main/scala/gemmini/LoadController.scala:113-128`; `G/src/main/scala/gemmini/StoreController.scala:185-194`.

The common memory/fence rule for **every command row below** is: configuration, compute, and preload do not themselves publish a result to CPU memory; MVIN reads memory into local storage and MVOUT writes local storage to memory asynchronously. LOOP_WS can generate both. CPU input stores must be ordered before DMA handoff; CPU reads must follow accelerator drain. `gemmini_fence()` is a CPU `fence`, **not a Gemmini funct7**: Rocket stalls a fence while RoCC or intervening RoCC pipeline stages are busy, and Gemmini busy covers command queues, unrollers, reservation station, and scratchpad. DMA writer busy includes outstanding TileLink acknowledgements, so a store controller completion alone is insufficient evidence of external visibility. Sources: `G/software/gemmini-rocc-tests/include/gemmini.h:339-345`; `C/generators/rocket-chip/src/main/scala/rocket/RocketCore.scala:346-358`; `G/src/main/scala/gemmini/Controller.scala:329-330`; `G/src/main/scala/gemmini/Scratchpad.scala:294-313,444`; `G/src/main/scala/gemmini/DMA.scala:390-401`. End-to-end coherence on an unspecified non-Rocket integration is **UNVERIFIED**; the cited Rocket contract must not be generalized.

The audited Gemmini inline assembly has no compiler `"memory"` clobber, including the bare `gemmini_fence()` macro. That is a compiler-ordering gap relative to PoTAL's wrappers, which explicitly clobber memory and issue `fence rw,rw`; it does not change the hardware busy test. Sources: `G/software/gemmini-rocc-tests/rocc-software/src/xcustom.h:115-152`; `G/software/gemmini-rocc-tests/include/gemmini.h:341`; `L/ggml/src/ggml-potal/include/potal_rocc.h:37-51,164-168`.

Invalid ordinary Gemmini commands do **not** have a general error-status response contract. Unknown functs reaching allocation hit the reservation station classification assertion. Many operand errors assert or truncate instead of returning an exception code; a silicon trap/recovery behavior for arbitrary malformed instructions is **UNVERIFIED**. This rule applies to every non-responding command in the tables, with additional restrictions listed there. Sources: `G/src/main/scala/gemmini/Controller.scala:358-401`; `G/src/main/scala/gemmini/ReservationStation.scala:295-307`; `G/src/main/scala/gemmini/LoadController.scala:136,189-190`; `G/src/main/scala/gemmini/StoreController.scala:217-218`.

### Local row addresses

The 32-bit local word is separate from a DMA virtual byte address. Layout: bit31 accumulator selector; bit30 accumulate on ACC writes; bit29 read full ACC width; bits28:26 `NormCmd` (3 bits); low `M=max(ceil(log2(SP banks*SP bank rows)),ceil(log2(ACC banks*ACC bank rows)))` bits are row data; bit M is `garbage_bit`; bits25:M+1 are unused garbage padding. Garbage recognition requires all three high flags, all low data bits, and garbage_bit set; `0xffffffff` is the software sentinel. Padding and norm bits are not part of that predicate. Sources: `G/src/main/scala/gemmini/LocalAddr.scala:6-44,94-100`; `G/src/main/scala/gemmini/NormCmd.scala:8-9`; `G/src/main/scala/gemmini/GemminiISA.scala:61`; `G/software/gemmini-rocc-tests/include/gemmini.h:78`.

For confirmed Gemmini D16, M=14, SP row bits11:0, SP bank bits13:12, ACC row bits8:0, ACC bank bit9. Thus SP rows range 0..16383; ACC rows 0..1023 total, split into two banks of 512. These are **DERIVED from this configuration**, not assumed for other Gemmini configurations. Sources: `G/src/main/scala/gemmini/LocalAddr.scala:9-17,33-39`; `G/src/main/scala/gemmini/Configs.scala:29-42`; `G/src/main/scala/gemmini/GemminiConfigs.scala:99-110`; `S/gemmini_params.h:8-12`. PoTAL's independently confirmed local widths are tabulated in `hardware-parameters.md`.

### COUNTER (funct7=126)

Custom-3, `xd/xs1/xs2=1/1/1`, returns a counter value to rd. rs1 bits: 0 global reset; 1 snapshot reset; 2 snapshot capture; 3 configuration write enable; 6:4 counter index(3 for the default eight counters); 17:12 event selector(6); 31 external flag; 11:7,30:18,63:32 ignored by this decoder. rs2 ignored (the software macro passes an otherwise unused placeholder). The event selector is valid only for available events/external values; malformed selectors are not converted into a status error. Sources: `G/src/main/scala/gemmini/GemminiISA.scala:56`; `G/src/main/scala/gemmini/GemminiConfigs.scala:83`; `G/src/main/scala/gemmini/CounterFile.scala:13-89,198-212,225-263`; `G/software/gemmini-rocc-tests/include/gemmini.h:349-394`; `S/gemmini.h:350-395`.

Counter width is **outer.xLen**, hence64 bits under the RV64 envelope used here; external event values are32 bits. The SDK's counter_read returns uint32_t and therefore exposes only the low32 bits, not the full RTL counter width. Acceptance latches the selected counter and rd into a response register, and response backpressure blocks another access. It does not fence DMA or compute; snapshot is counter-state capture, not memory publication. Sources: `G/src/main/scala/gemmini/Controller.scala:58-60,383-387`; `G/src/main/scala/gemmini/CounterFile.scala:91,183-205,231-263`; software result type `G/software/gemmini-rocc-tests/include/gemmini.h:355-360`. PoTAL's COUNTER wrapper returns uint64_t and includes capability-query extensions; those query tags must not be interpreted as ordinary Gemmini counter selectors (`L/ggml/src/ggml-potal/include/potal_rocc.h:134-138`; `P/PoTalResidentView.scala:17-19,36-60`; `P/PoTalStream.scala:24-31`).

## PoTAL

### Envelope, responses, and shared implementation

PoTAL extends the Gemmini-shaped custom-3 interface with functs23..30. The extension values come from `P/GemminiISA.scala:37-51`, identically `W/GemminiISA.scala:37-51`. SCALE/INDEX/FENCE use a separate ingress ahead of loop unrolling. Responding calls use `xd/xs1/xs2=1/1/1`; CONFIG/legacy LOOP_WS retain `0/1/1`. Software uses a compiler memory clobber in both cases. Sources: `P/Controller.scala:324-391`; `L/ggml/src/ggml-potal/include/potal_rocc.h:7-13,27-51`; `L/ggml/src/ggml-potal-w4a4/include/potal_rocc.h:27-51`.

For scale/index/fence, rd data is zero-extended status: 0 OK, 1 INVALID_COLUMN, 2 INVALID_SCALE, 3 SCALE_CONFLICT, 4 RELEASE_MISS, 5 INVALID_ADDRESS, 6 INVALID_ENCODING, 7 BAD_COMMAND. There is one pending ingress response. Importantly, ingress registers a response on **every** cmd.fire, even if malformed xd=0; canonical use must set xd=1. Do not assume invalid xd=0 is silently ignored in this ingress. Loop extensions instead explicitly avoid unsolicited writes when xd=0. ### PoTAL LOOP_WS fields and scale alignment

PoTAL retains funct8 and the Gemmini lower control bits, adding rs1 bit3 resident extended run, bit20 enable, bits36:21 scaleBase(16), bits44:37 scaleGeneration(8), bits60:45 passesPerBlock(16), bit61 paired ACC, bit62 residual ACC selection, bit63 indexed weights. rs2 bits31:3 A bank-local offset in D-row tiles(29), with63:32 reserved in acknowledged extended/stream forms. Scale block alignment is in **K elements**, not a CPU address alignment: scaleBlockK=D*passesPerBlock, with whole D-wide K passes per block. For output column c and tile j, slot = scaleBase + blockIndex*outputTileCount + j; the generation must hit in each active column's scale memory. Partial padded output columns do not require a hit. ### Sat32 arithmetic: shift the new partial, then add

For a raw mesh partial p, SCU produces `q = Sat32(p << carrier)` for a valid shift carrier, or q=0 for the zero carrier. Any nonzero p with carrier>=32 saturates to INT32_MIN/MAX according to sign; zero p stays zero. It does **not** wrap a large exponent to its low five bits, despite shiftAmount using those bits internally: the explicit >=32 branch overrides it. Sources: `P/PoTalSCU.scala:31-60`; `W/PoTalSCU.scala:31-60`.

SCU receives the **new raw partial**, not old ACC contents. First contribution writes q; later contributions compute `ACC_new = Sat32(ACC_old + q)` in the ACC read/modify/write adder. Old accumulated value is never shifted by this carrier. There are two saturation points: partial scaling, then ACC addition; replacing this with `Sat32((ACC_old+p)<<s)` or a single saturation on an unbounded scaled sum changes the contract. Sources: `P/PoTalWriteback.scala:241-255,278-302`; `P/AccumulatorMem.scala:71-87,160-163`; identical arithmetic `W/PoTalWriteback.scala:241-255`; `W/AccumulatorMem.scala:71-87`. Controller actually instantiates writeback when enablePoTalSat32Acc is true, despite stale configuration comments/enablePoTalWriteback=false (`P/Controller.scala:125-165,177-189`; `P/PoTalConfigs.scala:20-21,110-115`).

### INT4 storage and packing ABI

`potalw4` D32 is signed4-bit input arithmetic with signed32-bit ACC, while software `elem_t` is still an int8_t scalar container. `POTAL_PACKING_ABI=1` means transport packs adjacent signed two's-complement nibbles: even column in byte bits3:0, odd column in7:4. Scalar range -8..7; row byte count ceil(cols/2); checked packer zeroes padding and an odd final high nibble. D32 SP row is exactly16 bytes, not `DIM*sizeof(elem_t)=32`; packed byte buffers must not be confused with logical scalar arrays. Sources: `W/PoTalConfigs.scala:142-147`; `H/gemmini_potal_w4a4_d32_params.h:17-27`; `W/GemminiConfigs.scala:313-323,408-416`; `L/ggml/src/ggml-potal-w4a4/include/potal-int4.h:8-26,29-63`; `L/ggml/src/ggml-potal-w4a4/potal.c:38-42`.

DMA narrow row sizing is rounded from logical count*input bits; INT4 loop validation converts logical input stride to bytes, while load configuration carries byte stride. ACC row remains D*4=128 bytes. The header's row_align macro still uses DIM*sizeof(elem_t); it is over-alignment for the16-byte packed row, not a new packing definition.
